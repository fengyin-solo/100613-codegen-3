# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 掘进工程量计量支付规则

业务流程：按环次区间登记工程量确认单 → 监理签认 → 生成计量支付单 → 确认支付（留档）。

- **核定口径只有一份**：`frontend/src/data/measure-policy.ts`，版本化管理（如 `v2026-09` 存量口径、
  `v2026-10` 现行口径），分档上限、金额公式、环次重叠判定、缺环号补齐规则都是这份文件里的
  可复用判定函数，页面与服务不各自另写。
- **本期金额** = 确认工程量 × 支付比例（百分数），保留两位小数。
- **分档上限**：支付比例按所报计量档位校验合同上限（现行口径：月度计量档 80%、交工计量档 90%、
  竣工结算档 97%）。超档的条目直接拦下、不允许保存，报文里点明超出的是哪一档。
- **监理签认前置**：确认单未签认不允许生成支付单；只有「监理方」角色的账号能签认/驳回，
  项目内部账号的签认改动一概驳回（服务层强制，页面顶部可切换角色验证）。
- **重复报量**：同一环次允许不同班组各报一次，但签认时与已签认区间重叠的一律驳回，
  只认第一次签认的量；一张确认单只出一张支付单。
- **口径切换**：在计量支付页切换口径版本后，全部待支付单按新口径重算；比例超新上限的单
  标记异常、保留原金额待调整，不写入超限金额；已支付单按支付当时的口径与金额留档，不再变动。
- **同源结论**：进度节点页的「计量支付待办清单」与结算台账都读 `measureSummary()` 和支付单
  原表，两处看到的本期金额是同一份数，不会分成两份。
- **幂等与原子性**：确认单号、支付单（按关联确认单）均唯一，重复提交/重复生成直接拦截不翻倍；
  写库走 `saveMany` 原子提交——先落 localStorage 成功才换内存，入库失败一律不落。
- **存量补登**：`frontend/src/data/legacy-quantity.ts` 里的存量记录按「缺环号补齐规则」落位后
  按连续环号归并成环次区间确认单（来源标记「存量补登」，状态待签认）；与既有确认单环次重叠的
  区间跳过，重复执行不翻倍。

缺环号补齐规则（`fillLegacyRings`）：

1. 存量记录按「登记日期升序、单号升序」排队；
2. 有环号的按原环号落位；
3. 缺环号的接在队列中前一条记录的环号之后顺延（前一条也缺号则继续顺延）；
4. 队首连续缺号的，以队列中第一条有环号记录的环号为基准按位置向前倒推；
5. 整批都没有环号的，从第 1 环起顺排。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 工程量计量支付的规则（签认权限、分档上限、首次签认优先、口径重算、存量补登）集中在
  `frontend/src/api/measure-service.ts`，同样只由服务层改数据，页面只传参。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。
